## ما تحقّق محليًا وعلى الهاتف (المرحلة 0 والمرحلة 1)

- **المرحلة 0 (مكتملة):** تطابق اسم المستخدم، منع إعادة استخدام إثبات التسجيل، الكتابة خارج خيط الواجهة، بقاء النماذج المفتوحة أثناء المزامنة، استيراد أكثر من 999 صفًا، وحذف الكود الميت.
- **فحص الهاتف (Redmi M2101K7BI، Android 13، MIUI):** نجحت فحوص `LedgerCorrectnessInstrumentation` التسعة (`com.sadad.qa.correctness`) بعد السماح بفتح النوافذ في الخلفية (`appops 10021 allow`). نجح التدفق اليدوي على `com.sadad.app`: إضافة شخص ودين ودفعة بلا شبكة (`pending=1`)، ثم مزامنة تلقائية (`pending=0`) مع بقاء النص المكتوب في نموذج الدين أثناء المزامنة.
- **المرحلة 1 (الأدوات وتنظيف التوثيق):** `./tools/check.sh` هو بوابة الفحص الموحدة محليًا وفي CI، وتوثيق الوكلاء والشجرة مُنظَّفان وأدوات التنسيق والتدقيق (Spotless/ktfmt وdetekt و`deno fmt`/`deno lint`) مدمجة في القسم `format` (التذكرة 13، التزام 5081ede). سلسلة أدوات Kotlin (14) لم تبدأ.

## المعلّق وغير المحقّق

- **تطبيقات السحابة:** لا تغييرات سحابية معلّقة من المرحلة 0؛ إعادة ضبط مشروع الاختبار السحابي وتطبيق المخطط الأساسي الموحّد ونشر وظيفة `api` تنتظر المرحلة 2 وموافقة المستخدم الصريحة. استرجاع السحابة الكامل بصلاحياته وسياساته غير محقّق.
- **فحوص الأجهزة:**
  - لا يتوفر هاتف أقدم من Android 11، فحد 999 متغيرًا في SQLite مثبت بنيويًا فقط (غير محقّق على جهاز API < 30).
  - سيناريوهات `revoke-all` مع إنهاء الجلسات، وتبديل الحسابات `A→B→A`، واسترداد إدخالات معلقة حي، وفحص `Ui254` غير محقّقة.
- **توقيع الإنتاج:** مفتاح توقيع الإنتاج الرسمي وأسراره الأربعة (`SADAD_KEYSTORE_*`) غير متوفرة بعد (غير محقّق؛ مجدول للمرحلة 4).
- **عيوب مفتوحة في تطبيق Java الحالي (تنتهي بحذفه في المرحلة 3):**
  1. شاشة الشخص تبقى على الرصيد القديم بعد حفظ دين أو دفعة حتى إعادة تشغيل التطبيق.
  2. غياب الشبكة يعرض رسالة Java الخام (`Unable to resolve host …`) بدل رسالة عربية.
  3. مهلة الدخول (10 ثوانٍ) أقصر من التشغيل البارد للخادم (11.7 ثانية)؛ الإصلاح في الفرع `claude/unruffled-noether-252deb` (`7505c78`) غير مدمج وغير محقّق على الهاتف.

## المرحلة التالية

وفق قرار المستخدم (15 أكتوبر 2026) في [`docs/ARCHITECTURE.md`](ARCHITECTURE.md) الجزء 3، جميع المتاجر والبيانات تجريبية، والتنفيذ يتبع قاعدة القطع النظيف بلا ترحيل بيانات أو توافق قديم:

1. **إتمام المرحلة 1:** سلسلة أدوات Kotlin/Compose.
2. **المرحلة 2 — الخادم واللوحة الجديدة ثم القطع (تذاكر 21–28):** مخطط أساسي واحد في `Supabase-Setup/supabase/schemas/`، وهوية Supabase Auth وحدها، ووظيفة Edge واحدة `api` (Hono + zod)، ولوحة إدارة بـTypeScript + Vite، ثم إعادة ضبط مشروع الاختبار السحابي وحذف الوظائف الثلاث القديمة. (يتوقف تطبيق Java الحالي عن العمل بعد إعادة الضبط حتى تبديل المرحلة 3، وهي فجوة مقبولة).
3. **المرحلة 3 — تطبيق Android الجديد:** بناء `:ledger-core` و`:app` بـKotlin + Compose + Room + WorkManager، ثم حذف تطبيق Java والنسخة المستقلة كاملًا عند التبديل.
4. **المرحلة 4 — جاهزية الإنتاج:** `targetSdk 36`، مفتاح توقيع الإنتاج، ميزانيات الأداء، وتمرير الاستعادة.
